## 代码现状 vs 工单差距

### 1 · FB202607241055827 账单汇率

**已有（部分满足）：**

- `bills` 表列：`currency` / `exchangeRate` / `amountCny`（`ensure-bill-fx-schema`）
- 账单列表已有「币种 / 原币金额 / 汇率 / 折合人民币」列（`customer/bills/page.tsx`）
- 明细弹窗与打印区有「币种·汇率 / 原币 / 折合 CNY」
- `buildUseBoxBill` / 超期费等通过 `billFxItems` 写入明细行「汇率（对人民币）」

**仍存在的差距：**

| 差距 | 说明 |
|------|------|
| 本币账单观感 | CNY 账单汇率列显示「1.0000（本币）」，易被理解为「没汇率」 |
| 新账单类型 | 八月 D2 的维修费/上下车费/异常费账单未合并 `billFxItems`（当前全 CNY） |
| 历史数据 | 生产 11 张账单中 9 张 CNY；仅 2 张 EUR 能体现非 1 汇率 |
| 打印标题 | 打印模板固定标题「用箱账单」，非用箱类型账单打印易混淆 |

**结论：** 能力主干已在，工单更偏 **展示强化 + 境外线路账单样本 + 打印/明细一致性**，而非从零开发。

### 2 · FB202607271627184 + FB202607271628398 调运报价

**已有：**

- 价目维护页 `/config/dispatch-prices`（nav：**基础数据字典 → 调运价目**，R00/R01）
- 生产库 **12 条启用** `dispatch_price_rules`（布达佩斯/杜堡/汉堡/马拉等）
- 调运申请页选「提箱堆场」后，下方卡片即价目方案（字段名：**允许还箱城市方案**，含单价）

**差距（纯 UX / 信息架构）：**

| 差距 | 说明 |
|------|------|
| 入口隐蔽 | 价目在「基础配置」，不在「调运管理」模块下，仪表盘无 M02 专属引导 |
| 文案不直观 | 申请页未出现「调运报价/价目」字样，测试人员按字面找不到 |
| 流程认知 | 需理解 BR-11：先维护价目 → 申请时选方案 → 审批 → 任务/还箱 |

**结论：** **不需要新表或新 API**；以导航、文案、引导卡片为主，0.5～1 天可关单。

### 3 · FB202607281046991 还箱流程与角色

**已有：**

- 单据中心 `/customer/documents`：提箱/还箱 Tab、现场确认 API（`confirm-pickup` / `confirm-return`）
- 角色：R03 上传还箱证明；R04/R06/R01 现场「确认收箱」
- 测试文档 `用户测试/05-提还箱现场执行与异常.md` 有完整用例

**差距（流程体验）：**

| 差距 | 说明 |
|------|------|
| 状态命名 | 现场确认放箱后订单为 **「提箱中」**（含已登记箱号），非「已提箱」，易误判流程卡住 |
| 缺少「还箱中」驱动 | 上传还箱证明 **不** 改订单状态；生产有订单长期停在「提箱中」 |
| 无逐步引导 | 页面无「当前角色下一步」提示（客户 vs 堆场 vs 箱管） |
| 管理侧无总览 | `/admin` 无还箱阶段待办/角色矩阵，管理员反馈「操作点不明确」 |

**结论：** 代码链路 **能跑通**，工单核心是 **状态机可读性 + 页面内操作引导 + 可选自动推进还箱中**。

## P1 · 调运报价可发现性（两条工单合并做）

### 要做

1. **调运申请页**（`/dispatch/apply`）
   - 页头或侧边增加醒目链接：「维护调运价目 → `/config/dispatch-prices`」
   - 价目卡片标题改为「调运报价方案（还箱城市 + 单价）」
   - 卡片展示 `unitPrice`、`overdue` 更明显

2. **工作台**（`/`）
   - M02 模块区增加快捷卡片「调运价目维护」（链到 `/config/dispatch-prices`）
   - 调运申请旁增加「测试前请先配置价目」一句说明

3. **导航（可选）**
   - 在「核心业务与调运管理系统」下增加只读入口「调运价目查看」给 R02；或审批页展示锁定单价摘要

### 验收

- [ ] R01 从仪表盘或调运申请 **30 秒内** 能打开价目页
- [ ] 选堆场后可见报价卡片且含单价
- [ ] 能完成一次调运申请提交（选方案 → 填承运商 → 提交审批）

### 关单备注

`调运价目入口与申请页报价方案可见；生产 12 条价目可测全流程`

## P2 · 账单汇率体现

### 要做

1. **列表强化**
   - CNY 账单汇率列改为「本币（CNY）」或折叠显示，非 CNY 高亮
   - 类型筛选增加「外币账单」快捷（currency ≠ CNY）

2. **明细/打印**
   - 打印标题改为 `{detail.type}` 动态标题
   - 确保所有 `build*Bill` / `multi-bill-plan` 生成路径合并 `billFxItems`

3. **数据（生产）**
   - 抽检：境外线路订单触发的用箱/超期 EUR 账单是否带 `exchangeRate`
   - 必要时对历史 CNY 行补 `amountCny = amount`（迁移已有）

### 验收

- [ ] 外币账单列表、明细、打印均可见汇率与折合人民币
- [ ] 新触发的 D2 账单明细含汇率行（即 CNY 也统一格式）

### 关单备注

`账单中心列表/明细/打印均体现币种与汇率；外币账单可核对折合人民币`

## P3 · 还箱环节与角色操作点

### 要做

1. **单据中心**（`/customer/documents` 还箱 Tab）
   - 每行订单增加「下一步」Badge（按 `status` + 当前 `roleId`）  
     例：R03→「请上传还箱证明」；R04→「请现场确认收箱」
   - 页顶增加折叠「还箱协作说明」（角色 × 动作表，链到测试文档）

2. **状态机（小改，可选但建议）**
   - 上传还箱证明成功 → 订单 `status: 还箱中`（若当前为提箱中/已提箱）
   - 确认收箱成功 → `已完成`（已有）

3. **订单处理 / 管理中枢**
   - `/operations/usebox` 或 `/admin` 增加「还箱待办」统计：已提箱/还箱中且未 `returnGateAt`
   - 点击跳转单据中心还箱 Tab 并带筛选

4. **文档**
   - 在 `用户测试/01` 或 `05` 补一张「还箱阶段角色矩阵」截图位（便于 UAT）

### 验收

- [ ] 从提箱确认到还箱确认，测试人员按页面提示能走通
- [ ] R03、R04 各自只看到本角色应做的按钮
- [ ] 管理员能在中枢看到还箱阶段待办数

### 关单备注

`还箱阶段页面引导与角色下一步提示；可选上传证明后进入还箱中；管理侧还箱待办可见`
